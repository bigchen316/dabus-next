# 大巴设计规范 v1.1

> **DA BA DESIGN SYSTEM** ｜ 把复杂的东西讲成人话，把每一站做得有记忆点
>
> 适用：大巴个人网站、文章页、教程页、社交媒体封面、内容卡片、活动 Landing Page。
> 当前落地参考：`../dabus-next/app/globals.css`、`../dabus-next/components/`。
> 方法论来源：ESTHER 不二 / esther-design-system（CC BY-NC-SA 4.0）；品牌内容归「大巴」所有。

## 0. 这份规范怎么用

这不是灵感收藏，而是做决定时的优先级。

### 决策顺序

1. 先保证内容说清楚、入口找得到。
2. 再保证页面一眼认出是大巴。
3. 最后才增加装饰、动效和视觉惊喜。

### 三层规则

| 层级 | 含义 | 例子 |
|---|---|---|
| **必须** | 违反就需要返工 | 暖底、标题衬线、正文无衬线、可点击入口必须是真链接 |
| **建议** | 默认采用，有明确理由才偏离 | 车票、站点、路线图母题；黄黑绿关系 |
| **可选** | 用来制造变化 | 手写字、时间线、出血色块、Scroll Reveal |

### 交付前的一句话检查

> 这是一个真实的人在分享真实体验，还是一个套了黄色的通用 AI 模板？

## 1. 品牌核心：大巴是什么

### 品牌定位

- **品牌名**：大巴 / Da Ba / 大巴Bus
- **角色**：一个把 AI 工具、效率方法和动漫日常讲成人话的普通上班族
- **主要受众**：想少走弯路、但不想被术语和营销话术吓退的普通人
- **一句话人设**：一辆开在内容公路上的大巴车，乘客是愿意一起往前走的人
- **核心承诺**：亲自试过再说；能干嘛、怎么上手、值不值，一次讲清楚

### 四个气质关键词

1. **在路上**：车票、站牌、路线、到站广播，服务于内容叙事。
2. **说人话**：先讲结论，再讲过程；不端、不玄、不故意复杂。
3. **暖而直接**：有阳光感，但不幼稚；有态度，但不攻击。
4. **粗线条有细节**：边框、编号、虚线、色块要果断，信息层级要克制。

### 明确不要变成什么

- 不做泛泛的「AI 专家」人设。
- 不做旅游宣传册式的巴士主题装饰。
- 不做冷灰蓝、玻璃拟态、霓虹渐变的科技模板。
- 不用复杂动效掩盖内容不足。
- 不把所有模块都套成卡片。

## 2. 色彩系统

### 2.1 核心 Token

```css
:root {
  /* 品牌三色 */
  --daba-yellow: #FFC400; /* 交通黄：行动、阳光、重点 */
  --daba-ink:    #1A1A1A; /* 柏油黑：文字、结构、边框 */
  --daba-green:  #00C853; /* 信号绿：状态、确认、路线节点 */

  /* 页面底色 */
  --daba-bg:     #FEFCF6; /* 暖白主背景 */
  --daba-cream:  #FAF6EB; /* 深奶辅助背景 */
  --daba-surface:#FFFFFF; /* 卡片表面，可用但不要铺满整页 */

  /* 深色面板 */
  --daba-dark:   #151821;

  /* 文字层级 */
  --daba-text:   #1A1A1A;
  --daba-muted:  #4A4A5A;
  --daba-faint:  #8A8A96;

  /* 语义状态 */
  --daba-focus:  #1A1A1A;
  --daba-danger: #B42318;
}
```

### 2.2 使用原则

原来的「60 / 30 / 10」是**视觉层级提示，不是像素面积配额**。不要为了凑比例把页面涂满黄色。

| 层级 | 默认颜色 | 用途 |
|---|---|---|
| 页面底 | `--daba-bg` / `--daba-cream` | 页面大面积背景，保持暖感和呼吸感 |
| 结构与正文 | `--daba-ink` / `--daba-muted` | 标题、正文、边框、深色面板 |
| 行动与重点 | `--daba-yellow` | CTA、重点色块、票卡阴影、标题高亮 |
| 信号与确认 | `--daba-green` | 状态灯、路线节点、标签、成功反馈 |

硬规则：

- 信号绿是**点缀色**，不要用作大面积背景或长段正文。
- 黄色面板上的文字使用柏油黑；不要黄底配黄字。
- 深色面板上的正文使用接近白色的中性色，黄色只用于关键词和行动点。
- `--daba-surface` 只表示内容表面，不等于新的页面背景。
- 正文和按钮文字必须通过对比度检查；不能只凭屏幕观感判断。

### 2.3 高亮与边框

```css
/* 默认文字高亮：像荧光笔，不像渐变字 */
background: linear-gradient(transparent 60%, rgba(0, 200, 83, .35) 60%);

/* 选中文字 */
::selection { background: var(--daba-yellow); color: var(--daba-ink); }
```

品牌边框可以粗，但不要求所有边框都粗。**外轮廓 2~4px、顶部色条 4~6px、强调色块按组件决定**，避免把「40px 不得更细」误用到所有边框上。

## 3. 字体与排版

### 3.1 字体角色

当前网站采用可直接加载、跨设备更稳定的字体组合：

| 角色 | 字体 | 用途 |
|---|---|---|
| 中文标题 | `Noto Serif SC` 700/900 | H1、H2、卡片标题、重要金句 |
| 中文正文 | `Noto Sans SC` 400/500/700 | 正文、导航、按钮、说明文字 |
| 英文装饰 | `Fraunces` italic/bold | ROUTE、STOP、章节编号、短标签 |
| 手写注释 | `Caveat` 600/700 | 轻量旁注、图注、情绪化短句 |
| 等宽信息 | `Fira Code` 400/500 | 票号、线路号、平台 handle、技术信息 |

`Huiwen Mincho` 可以作为创作海报的可选字体，但不作为网站必需依赖；网站正文不能因为缺字或未安装字体而失真。

### 3.2 字号阶梯

```css
--text-hero:  clamp(2.6rem, 6.5vw, 5rem);
--text-h2:    clamp(1.6rem, 4vw, 2.6rem);
--text-h3:    clamp(1.1rem, 1.8vw, 1.35rem);
--text-body:  clamp(1rem, 1.4vw, 1.15rem);
--text-small: .82rem;
--text-micro: .68rem;
```

使用规则：

- 一个页面只保留 1 个主 H1；H2 用于区分内容段落，不用来装饰。
- 标题可以很大，但正文不能被压缩到难读。
- 英文标签只承担导航和节奏，不承担核心信息。
- 正文行长控制在约 28~40 个中文字符；卡片正文更短。
- 中文正文默认行高 1.7~1.85，标题行高 1.15~1.35。
- 不用全大写英文承载长句，不用等宽字体冒充「科技感」。

## 4. 间距、容器与响应式

### 4.1 容器

```css
--content-max: 1300px;
--page-pad: clamp(1rem, 3vw, 2rem);
```

- 页面内容最大宽度：`1300px`。
- 文字内容必须再设置合理的 `max-width`，不能让长段文字铺满容器。
- 视觉上需要全宽的深色面板或黄色面板，内容仍放在统一容器内。

### 4.2 间距

```css
--space-section: clamp(72px, 10vh, 128px);
--space-block:   clamp(32px, 5vw, 72px);
--space-card:    clamp(20px, 2.6vw, 36px);
--space-gap:     clamp(16px, 2.5vw, 32px);
```

间距服务于内容节奏。若一屏只剩标题和大量空白，应优先收紧 section 间距，而不是继续增加装饰。

### 4.3 响应式

| 断点 | 处理重点 |
|---|---|
| `> 900px` | 双栏、三列、交错时间线 |
| `601px–900px` | 双栏收窄，必要时提前改单栏，避免卡片拥挤 |
| `≤ 600px` | 单栏、按钮可换行、票卡缩窄、导航保持可用 |

移动端原则：

- 是重新排列，不是简单缩小。
- 不隐藏核心内容；只能隐藏装饰性英文和非必要装饰。
- 触控目标建议至少 `44px` 高。
- 复杂交错时间线在小屏改为单侧路线，不保留空的另一半。
- 尊重 `prefers-reduced-motion: reduce`。

## 5. 巴士母题：少而准

一页默认选择 **1 个主母题 + 1 个辅助母题**。母题是信息结构，不是贴纸。

| 母题 | 适合表达 | 视觉做法 |
|---|---|---|
| 车票 | 平台入口、资源下载、联系方式 | 虚线票边、票号、检票信息、可点击整卡 |
| 站牌导航 | 页面导航、栏目切换 | 圆点、线路号、短标签、清晰 active 状态 |
| 路线图 | 经历、计划、教程步骤 | 节点、连接线、起点/途中/下一站 |
| 到站广播 | 观点、结论、内容预告 |「下一站——」句式 + 深色全宽面板 |
| 车窗 | 头像、作品图、案例主视觉 | 粗边框、轻微倾斜、黄色偏移阴影 |
| 里程统计 | 可验证的数量、进度、成果 | 只展示真实数字，不制造虚假社会证明 |

禁止：蓝天白云旅游插画做主视觉、真实巴士照片做 Hero、同一屏同时出现车票/站牌/路线/广播四套母题。

## 6. 布局与组件

### 6.1 布局原则

- 每页使用 2~4 种布局节奏即可，不要求每个 section 都完全不同。
- 同类内容使用同一种结构；变化应来自内容和色块，而不是无目的换布局。
- Hero 默认采用不对称双栏（约 `1 : .6`），避免机械的 50/50。
- 每个页面最多 1~2 个全宽品牌色面板。
- 卡片数量优先保持成组；只有真实内容只有 1~2 项时，不为了凑数虚构内容。
- 卡片不是默认答案：能用列表、时间线、短段落解决，就不要套卡片。

### 6.2 核心组件

| 组件 | 必须包含 | 交互/状态要求 |
|---|---|---|
| **站牌导航** | 品牌标识、当前页、主入口 | 当前页清晰；链接必须可键盘访问 |
| **Hero** | 身份、价值主张、一个主 CTA | 首屏 3 秒内能回答「你是谁、我能得到什么」 |
| **路线卡** | 线路名、标题、说明、频率/状态 | 同组高度和层级一致；不强行让整卡可点击 |
| **车票卡** | 票号、平台/入口、handle、说明 | 有真实 URL 才使用 `<a>`；占位入口要明确标注 |
| **路线时间线** | 起点、节点、下一站 | 小屏切为单侧；连接线不能遮挡正文 |
| **到站广播** | 结论、补充说明、少量入口 | 深色面板只承担一个重点信息 |
| **CTA 面板** | 一个主动作，最多一个次动作 | 主次关系明确；全站 CTA 不超过 3 个 |
| **页脚** | 站点、关注方式、版权 | 邮箱、外链必须是真实可用链接 |

### 6.3 状态规范

每个可交互组件至少考虑：默认、悬停、键盘聚焦、按下、不可用/占位、减少动效。

- 链接使用真实 `<a href>`，不要用 `div` 模拟链接。
- 外部链接按需要使用 `target="_blank"`，并补 `rel="noreferrer"`。
- 键盘聚焦不能只依赖浏览器默认 outline；要有明显且符合品牌的焦点样式。
- 占位内容要诚实说明「整理中 / 即将上线」，不能伪装成已可用入口。

## 7. 影像、IP 与素材

- 大巴 IP 优先使用内联 SVG 或可控的品牌插画，保证缩放清晰。
- 头像/插画可以有粗边框和轻微偏移，但不要叠加复杂滤镜。
- 真实截图只有在它能证明内容时才使用；不要用无意义 stock photo 填空。
- 图片必须有有意义的 `alt`；装饰性图片使用空 `alt`。
- Hero 视觉只保留一个主焦点；不要让头像、标题、装饰同时抢第一注意力。

---

## 8. 动效

### 默认方案

- 只使用一次性入场 Reveal、轻微位移、按钮 hover。
- 动效时长约 `400~700ms`，缓动使用平滑的 ease-out。
- stagger 间隔约 `80~120ms`，同组最多 5 个延迟层级。
- 动效不能改变布局尺寸，不能造成内容跳动。

### 禁止

- 无限循环动画、bounce、elastic、强烈旋转。
- 用动画替代加载状态或信息层级。
- 页面一打开所有内容同时闪入。
- 忽略 `prefers-reduced-motion`。

## 9. 文案与内容语气

### 写法

- 先说结论，再说理由和步骤。
- 用「能干嘛 / 怎么上手 / 值不值」拆解工具体验。
- 允许有个人口吻，但不把普通用户排除在外。
- 一句话尽量只表达一个动作或判断。
- 平台入口写清楚：平台名、账号名、用户能做什么。

### 避免

- 「赋能、闭环、颠覆、重新定义」等空泛营销词。
- 没有证据的「全网第一、最强、必看」。
- 为了显得专业而堆英文缩写。
- 把暂未完成的内容写成已上线。

### CTA 语气

优先使用：`上车`、`去看看`、`查看实测`、`去乘车指南`。

避免使用：`立即抢购`、`马上赢在起跑线`、`点击这里`。

## 10. SEO、无障碍与性能底线

- 每页只有一个 H1，标题层级按内容结构递进。
- 每页提供准确的 `title` 和 `description`。
- 图片有 `alt`；外链有可理解的链接文本。
- 文字与背景保持足够对比度；不能只依赖颜色传达状态。
- 所有入口可用键盘访问，焦点状态可见。
- 首屏图片不使用过大的无损文件；SVG 优先，位图需压缩。
- 不把远程字体当作唯一可用字体；必须有合理 fallback。
- 构建必须通过 TypeScript、Lint 和静态导出检查。

## 11. 页面模板建议

### 首页

`Hero 身份` → `三条线路` → `到站广播` → `路线图` → `一个 CTA`

首页的主要任务是让新访客知道你是谁，并找到一个下一步；不要在首页堆完整文章列表。

当前首页采用无头像路线版：Hero 只保留文字主张与内容路线标记，头像集中放在司机档案和 IP 实验页，避免首屏主焦点被人物图卡分散。

### 司机档案 / About

`身份标题` → `IP + 自我介绍` → `为什么做这件事` → `发车计划` → `页脚`

重点是建立信任，不是重复首页卖点。

### 乘车指南 / Contact

`说明标题` → `真实平台入口车票` → `邮箱/合作入口` → `占位说明`

平台没有直达链接时，必须明确写「用站名搜索」，不要把不可点击的卡片伪装成按钮。

### 内容文章页

`文章标题` → `一句话结论` → `实测过程` → `适合谁 / 不适合谁` → `下一站推荐`

文章页不必强行使用大量巴士装饰，保持阅读优先。

## 12. 工作流

1. **明确任务**：页面类型、受众、核心动作、真实素材。
2. **选母题**：一主一辅，先决定信息结构。
3. **搭骨架**：先完成标题、正文、链接和响应式结构。
4. **套 Token**：颜色、字号、间距、边框统一从变量取值。
5. **补品牌细节**：站点编号、车票虚线、广播句式、IP 图形。
6. **做状态**：hover、focus、占位、错误、减少动效。
7. **验证**：桌面端、小屏、键盘、构建、链接和首屏加载。
8. **再做装饰**：只有内容已经成立，才增加视觉惊喜。

## 附录 B · 反模式清单

出现以下情况，优先返工而不是继续加装饰：

- 蓝紫渐变、霓虹青、冷灰蓝科技模板
- 所有内容都被包进圆角白卡
- 所有 section 都是同一种居中布局
- 默认 `<blockquote>`、默认列表、默认表格直接出现在页面
- 用 `div` 模拟按钮或链接
- 真实链接缺失却写成「点击进入」
- 动效无限循环或导致页面跳动
- 黄色面板使用黄色文字
- 大段英文标签挤占中文信息
- 为了满足「卡片数量」虚构内容
- 看起来像 AI 生成的通用 Landing Page
